Тема варианта: компьютерный клуб. Программа демонстрирует инкапсуляцию,
цепочку конструкторов, перегрузку методов и статический учет оплаченных заказов.
Требуется Java 17 или новее. Внешние библиотеки не нужны.

Цель работы — спроектировать взаимосвязанные классы на Java и на примере расчёта стоимости заказа показать инкапсуляцию, цепочку конструкторов, перегрузку методов и работу статических полей и методов.

## Структура

| Класс | Назначение |
| --- | --- |
| `VRGlasses` | Название VR-очков и изменяемая цена минуты аренды с валидацией. |
| `GamingSeat` | Название места, базовая цена, зона, ссылка на подключенные VR-очки и расчет стоимости. |
| `CyberArena` | Точка входа, регистрация оплаты, общие счетчики и итоговый отчет. |

Все поля закрыты (`private`). Названия объектов неизменяемы (`final`).
Для чтения полей предусмотрены геттеры, для изменения цен и зоны — проверяющие сеттеры.
Связь с VR-очками устанавливается расчетным методом после успешной проверки параметров.
Сокращенный конструктор места вызывает полный через `this(...)`.

## Расчет стоимости

Базовая цена относится к одному заказу игрового места. Коэффициент зоны
выбирается через современное выражение `switch`:

| Зона | Надбавка | Коэффициент |
| --- | ---: | ---: |
| `Standard Zone` | 0% | 1.0 |
| `VIP Zone` | 40% | 1.4 |
| `BootCamp` | 100% | 2.0 |

Формула: **стоимость места = базовая цена × коэффициент зоны**.
Аренда VR добавляется отдельно: **цена минуты × число минут**.
Надбавка зоны применяется только к игровому месту.

- `calculateFinalPrice()` — стоимость места без VR.
- `calculateFinalPrice(vr)` — место и VR на одну минуту.
- `calculateFinalPrice(vr, minutes)` — место и VR на заданное количество минут.
- `addVR(vr)` и `addVR(vr, minutes)` — методы из таблицы варианта 27;
  они вызывают соответствующие перегрузки без дублирования формулы.

Общие требования документа используют имя `calculateFinalPrice`, а таблица
варианта — `addVR`, поэтому реализованы оба интерфейса.
В документе не задана длительность для вызова без `minutes`: в этой реализации
он означает **одну минуту**, а цена VR задается **за минуту**.
Повторный расчет заменяет ссылку на опцию и не накапливает доплаты.
Вызов без аргументов всегда возвращает цену места без VR, даже если опция уже связана.

Цены должны быть конечными и неотрицательными, названия — непустыми,
зона — одной из перечисленных, минуты — положительным целым числом.
Ошибочные значения вызывают `IllegalArgumentException` до изменения состояния.
Цены и результаты округляются до двух знаков методом `HALF_UP` через `BigDecimal`.
Глобальная выручка хранится в `double`, как требуется в задании;
сложение платежей выполняется через `BigDecimal` для обычных денежных сумм.

## Демонстрация и статистика

В `main` создаются одни VR-очки по 25 руб./мин. и три места с базовой ценой 1200 руб.

| Заказ | Вычисление | Стоимость |
| --- | --- | ---: |
| Standard, без VR | 1200 × 1 | 1200.00 руб. |
| VIP, VR на 1 минуту | 1200 × 1.4 + 25 | 1705.00 руб. |
| BootCamp, VR на 30 минут | 1200 × 2 + 25 × 30 | 3150.00 руб. |

Итог нового запуска: **3 оплаченных заказа, выручка 6055.00 руб.**
Статистика меняется только при вызове `CyberArena.registerPayment(amount)`.
Один вызов означает один оплаченный заказ, включая заказ с нулевой ценой.
Создание объектов и повторные расчеты не изменяют счетчики.
Последний вызов в `main` — `printGlobalStats()`.

## Что объяснить на защите

- **Инкапсуляция:** изменение закрытых полей возможно только через методы с проверками.
- **Агрегация:** VR-очки создаются отдельно; игровое место хранит ссылку на них.
- **Перегрузка:** компилятор выбирает метод по количеству и типам аргументов.
- **Цепочка конструкторов:** `this(...)` задает тариф по умолчанию через полный конструктор.
- **Статические поля:** счетчик и выручка общие для всего клуба в рамках запуска программы.
- **`final`:** название объекта и константы нельзя переназначить после инициализации.
